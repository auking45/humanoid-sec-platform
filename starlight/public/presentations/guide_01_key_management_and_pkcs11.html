Security Foundations 01

키 관리와 PKCS#11

왜 비밀키를 디스크에 저장하면 안 되는가?

Zero-Plaintext Key 철학 • SoftHSMv2 • PKCS#11 In-Token 서명 위임

The Hidden Danger

보안의 제1원칙

"디스크에 저장된 비밀키는 이미 해커의 키다"

많은 엔지니어가 chmod 600 id_rsa 로 설정하면 안전하다고 믿음.
하지만 파일 권한은 OS 커널이 정상일 때만 유효한 논리적 장벽일 뿐임.

  • 물리 칩오프(Chip-off): eMMC 플래시 칩 떼어내면 10초 만에 파일 전체 복제
  • 커널 취약점: 루트 권한(UID 0) 탈취 시 즉각 평문 키 유출(Exfiltration)
  • 메모리 덤프: 프로세스가 파일을 읽는 순간 물리 RAM / 코어 덤프에 노출
Industry Standard

하드웨어 보안 모듈(HSM)과 PKCS#11

PKCS#11 (Cryptoki)는 스마트카드, 하드웨어 보안 모듈(HSM),
그리고 Secure World와 통신하는 국제 표준 C API 인터페이스임.

🔒 Never-Extractable

키 생성 시 CKA_EXTRACTABLE=FALSE 플래그 강제.
어떤 관리자 명령으로도 하드웨어 밖으로 키를 꺼낼 수 없음.

⚡ In-Token C_Sign

키를 파일로 읽어오지 않고,
서명할 데이터(해시)를 토큰에 보내 서명값만 받아옴.

Architecture Comparison

평문 키 vs PKCS#11 서명 위임

❌ 취약한 기존 방식

App -> open("server.key") -> Disk
App <- [평문 비밀키 노출!] <- Disk
App -> 프로세스 RAM에서 직접 서명 연산
=> 메모리 덤프/해킹 시 키 영구 유출!

✅ 안전한 PKCS#11 방식

App -> 32바이트 해시 전달 -> HSM 토큰
HSM -> 하드웨어 내부에서 비공개 연산
App <- 결과 서명값(R, S)만 수신
=> 키 노출 0%, 덤프해도 탈취 불가능!
Standard Pointer

RFC 7512 PKCS#11 URI

우리 플랫폼은 설정 파일에 파일 경로를 절대 하드코딩하지 않음:

# 파일 경로가 아닌 토큰 내부 핸들 포인터 사용
pkcs11:model=SoftHSM%20v2;token=HumanoidSecToken;id=%01;object=KernelModuleSigningKey;type=private
  • 빌드 스크립트와 OpenSSL에 파일 대신 URI 포인터 전달
  • pkcs11-provider가 SoftHSMv2 또는 OP-TEE Secure World로 통신 중계
  • 토큰 PIN 번호는 환경 변수로 격리 주입
Key Architecture

3계층 키 라이프사이클

Tier 1: 오프라인 서명 환경 (SoftHSMv2)

커널 모듈 키, dm-verity 루트 해시 키, IMA 파일 서명 키 (빌드 머신 격리)

Tier 2: 디바이스 하드웨어 (OP-TEE & fTPM)

로봇 mTLS 고유 신원키, fTPM 원격 증명키(AK) (Secure SRAM 봉인)

Tier 3: 공개 검증 아티팩트 (Public Distribution)

커널 빌트인 공개키링, 디바이스 공개 인증서 (배포 안전)

Automated Quality Gate

무평문 키(Zero-Plaintext) 감사

Git 커밋 전 및 CI/CD 빌드 파이프라인에서
keys_hsm/audit_zero_keys.sh가 전수 검사를 강제함: 

$ ./humanoid.sh setup
[*] Scanning git-tracked files for plaintext private keys...
[OK] All git-tracked files verified clean (0 plaintext private keys).
[OK] Workspace verified clean (0 plaintext private keys in source paths).
[OK] Zero Plaintext Key Policy: PASSED

평문 키 패턴(PEM 헤더)이 단 1개라도 감지되면 즉시 빌드 및 커밋 차단!

Key Takeaway

핵심 요약 & 실무 지침

  • 비밀키 파일 금지: .pem, .key를 디스크에 저장하는 관행 탈피
  • 하드웨어 격리: SoftHSMv2 및 TrustZone OP-TEE 토큰에 키 봉인
  • 서명 위임: C_Sign API를 통해 해시만 전달하고 결과 서명만 수신
  • 표준 URI: RFC 7512 pkcs11: 포인터로 인프라 표준화
