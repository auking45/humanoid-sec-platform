HARDWARE ROOT OF TRUST

NVIDIA Jetson Secure Boot & Stage 2 UEFI db

양산 휴머노이드 로봇 부팅 무결성 및 암호화 부트로더 파이프라인

NVIDIA JetPack 7.2.1 (L4T R39.2.1) • Tegra Orin / Thor • RSA-3072 PKC • EKB v2.1

휴머노이드 로봇에서 Secure Boot가 필수적인 이유

🚨 물리적 접근 위협 (Physical Threat)

  • 원격 서버와 달리 로봇 본체에 공격자가 직접 물리 접근 가능.
  • eMMC/UFS 플래시 칩을 분리하거나 UART/JTAG을 통해 악성 커널 주입 시도.
  • 보안 부팅 부재 시 모터 제어 신호 탈취로 인명 충돌 및 물리적 상해 유발.

🛡️ 하드웨어 기반 방어 (Hardware Defense)

  • SoC 내부 읽기 전용 BootROM과 eFuse를 신뢰의 기점(Root of Trust)으로 강제.
  • 암호화 서명 검증 통과 전까지 CPUBL 및 OS 실행 원천 차단.
  • 오프라인 서명 키와 하드웨어 키를 바인딩하여 무인가 펌웨어 로드 100% 방어.

전체 Secure Boot 신뢰 체인 (Chain of Trust)

BootROM (EL3) → TF-A BL31 → OP-TEE (S-EL1) → UEFI db (CPUBL) → L4T Kernel (NS-EL1) → EROFS dm-verity

NVIDIA Tegra SoC eFuse 레지스터 아키텍처

SoC 생산 시 단 1회 비가역적(OTP)으로 소각(Burn)되는 핵심 보안 퓨즈:

  • SecurityMode (0x1): Production Secure Boot 강제 (비인가 부팅 전면 차단).
  • BootSecurityInfo (0x00000209): 0x1 RSA-3072 PKC | 0x8 SBK 암호화 | 0x200 BSI_OEM_KEY_VALID.
  • FUSE_PKC_HASH: SoftHSMv2 SecureBootKey (RSA-3072) 공개키의 SHA-256 / SHA-512 해시값.
  • FUSE_SECURE_BOOT_KEY (SBK): 부트로더 페이로드 암호화용 256비트 AES 대칭키.
  • OemK1 / OemKdk0: EKB 및 fTPM/디스크 암호화 루트 키를 유도하는 256비트 제조사 전용 퓨즈.

공식 <genericfuse> XML 규격 및 관리

NVIDIA 공식 odmfuse.sh 및 fskp_fuseburn.py와 100% 호환되는 명세:

EKB (Encrypted KeyBlob) v2.1 아키텍처

NVIDIA 공식 gen_ekb.py 기반 NVEKBP\0\0 바이너리 구조 (build/images/eks_t234.img):

  • OemK1 기반 암호화: NIST SP 800-108 CMAC KDF(T234) / KBKDF-HMAC-SHA256(T264) 유도.
  • Tag 1 (sym_key, 32B): UEFI/CPUBL 커널 및 DTB 페이로드 복호화 대칭키.
  • Tag 2 (sym_key2, 16B): LUKS 디스크 파티션 암호화 마스터 키.
  • Tag 4 (auth_key, 16B): OP-TEE RPMB 기반 UEFI Authenticated Variable 서명 인증키.
  • Tag 91/92 (ftpm_sn, ftpm_eps_seed, 64B): fTPM 고유 신원 증명 및 EPS 엔트로피 시드.

8KB NVDA Boot Component Header (BCH) 규격

jetson_uefi_services.h 표준을 따르는 8,192바이트 바이너리 헤더 레이아웃:

  • Offset 0x0000 (0): 'NVDA' 매직 (BCH_HEADER_MAGIC)
  • Offset 0x0098 (152): UEFI db Public Key SHA-256 Hash (32B)
  • Offset 0x0100 (256): Stage 1 BootROM/MB2 PKC RSA-3072 Signature (384B)
  • Offset 0x0280 (640): Stage 2 UEFI db RSA-3072 Signature (384B)
  • Offset 0x1400 (5120): 'BCRT' 매직 + 80B AAD (KDF 레이블 CPUBL-PAYLOAD-DK, IV)
  • Offset 0x1450 (5200): AES-256-GCM 16-byte Authentication Tag
  • Offset 0x2000 (8192): 암호화된 커널 페이로드 시작점 (ISO/IEC 9797-1 Method 2 패딩)

2단계 서명 검증 게이트 (Dual-Stage Gate)

Stage 1: Hardware Gate (MB2/PKC)

  • eFuse에 등록된 FUSE_PKC_HASH와 BCH 헤더의 PKC 공개키 대조.
  • 부트로더 컨테이너의 Stage 1 RSA-3072 서명 무결성 검증.
  • 불일치 시 하드웨어 부팅 즉시 정지.

Stage 2: UEFI db Gate (CPUBL)

  • SoftHSMv2 KernelModuleSigningKey (ID 01) 공개키로 Stage 2 서명 검증.
  • EKB Tag 1 sym_key로부터 유도된 AES-256-GCM 복호화.
  • 서명 훼손 시 SECURE_BOOT_VIOLATION 발생.

5종 공격 방어 실증 (Tamper-Resistance)

공격 시나리오 공격 벡터 방어 메커니즘 결과
ATK-01A 커널 암호문 1바이트 변조 (Offset 8200) AES-256-GCM Tag 검증 실패 BLOCKED
ATK-01B 미인가 PKC 사설 서명키 주입 SoC eFuse FUSE_PKC_HASH 불일치 BLOCKED
ATK-01C EKB (eks_t234.img) 1바이트 변조 OEM_K1 기반 CMAC KDF 복호화 실패 BLOCKED
ATK-06 Stage 2 UEFI db 서명 변조 (Offset 650) UEFI db RSA-3072 검증 실패 BLOCKED

실제 Jetson 보드 양산 플래싱 연동

QEMU 검증 아티팩트를 실제 물리 하드웨어 배포에 1:1 재사용:

# 1. Jetson Orin/Thor 복구 모드 진입 후 영구 eFuse 소각 (양산 1회)
./scripts/flash_jetson_hardware.sh --fuse --chip t234

# 2. PKC, UEFI db, EKB 이미지를 L4T bootloader/ 디렉토리에 스테이징
./scripts/flash_jetson_hardware.sh --stage-keys --chip t234

# 3. NVIDIA 공식 l4t_initrd_flash.sh를 통한 EROFS + dm-verity 배포
./scripts/flash_jetson_hardware.sh --flash-all --chip t234

하드웨어 시험 전 QEMU (./scripts/run_qemu.sh --secureboot)에서 사전 100% 검증.

핵심 요약 (Key Takeaways)

  • 물리적 공격 원천 차단: 칩 분리, 펌웨어 변조, 사설 서명키 주입 공격을 BootROM 레벨에서 100% 차단.
  • NVIDIA 공식 2단계 규격 준수: MB2 (Stage 1 PKC) 및 UEFI (Stage 2 db) 8KB NVDA BCH 컨테이너 완벽 호환.
  • Zero Plaintext Key 준수: 모든 서명키는 SoftHSMv2 PKCS#11 토큰 내부에 격리되어 평문 유출 불가.
  • 자동화 회귀 검증 체계: tests/test_secureboot_chain.py를 통해 CI/CD 파이프라인에서 지속 검증.
