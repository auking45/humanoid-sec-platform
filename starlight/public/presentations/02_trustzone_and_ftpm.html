SECURE WORLD ISOLATION

ARM TrustZone, OP-TEE OS & fTPM 2.0

하드웨어 메모리 격리 기반 TEE 및 변조 불가 보안 실행 환경 구축

OP-TEE 4.2 • ms-tpm-20-ref • S-EL1 Trusted OS • eMMC RPMB Anti-Rollback

Normal World 침해 시 왜 TEE가 필요한가?

💥 커널 장악 시나리오 (Kernel Compromise)

  • ROS 2 노드 또는 커널 취약점으로 공격자가 링 0 최고 권한 획득.
  • 일반 OS 구조에서는 커널 권한 탈취 시 모든 메모리와 인증키가 노출됨.
  • 공격자가 임의로 TPM PCR을 리셋하거나 위조 서명을 생성할 위험.

🏰 TrustZone 하드웨어 성벽 (Hardware Wall)

  • ARM TrustZone(EL3/S-EL1)은 커널조차 침범할 수 없는 하드웨어 격리 영역.
  • 인증키는 오직 S-EL0 Trusted Application 내부에서만 연산.
  • 리눅스 커널이 전면 장악되어도 TEE 내부 개인키 및 fTPM NVRAM 탈취 불가.

TZDRAM 물리 메모리 방화벽 (TZASC)

QEMU 및 실제 Jetson 하드웨어에서 TZDRAM 메모리 주소 매핑 및 보호 구조:

  • Secure TZDRAM (0x0e100000 ~ 0x10000000, 32MB):
    • ARM TZASC (TrustZone Address Space Controller)로 NS(Non-Secure) 비트 접근 차단.
    • Normal World(리눅스 커널)가 해당 주소 읽기/쓰기 시도 시 하드웨어 Bus Error 발생.
  • Non-Secure RAM (0x40000000 ~, 1GB ~ 64GB):
    • L4T 커널 및 사용자 공간이 공유 메모리(SHM) 풀을 통해서만 파라미터 전달.

OP-TEE 4.2 Core 및 Early TA 탑재 아키텍처

부팅 초기 Normal World 파일시스템 마운트 전에 필수 보안 TA를 S-EL1 펌웨어에 내장:

  • Early fTPM TA (CFG_IN_TREE_EARLY_TAS):
    • 리눅스 부팅 초기 IMA 측정 및 PCR 확장을 위해 부트로더 단계에서 fTPM TA 사전 로딩.
  • PKCS#11 TA (CFG_PKCS11_TA=y):
    • mTLS 클라이언트 인증서 개인키를 Secure SRAM에 봉인하고 C_Sign API 제공.
  • SMC (Secure Monitor Call) 프로토콜:
    • Normal World의 /dev/tee0 드라이버가 EL3 TF-A를 경유하여 S-EL1 OP-TEE와 통신.

ms-tpm-20-ref 기반 fTPM 2.0 엔진

물리 dTPM 칩 없이도 TEE 내부에서 표준 TCG TPM 2.0 스펙을 100% 충족:

  • 인터페이스: Linux 커널 drivers/char/tpm/tpm_ftpm_tee.c → /dev/tpmrm0.
  • 표준 명령 지원:
    • TPM2_PCR_Extend(PCR 10): 부팅 및 런타임 실행 바이너리 SHA-256 누적 연산.
    • TPM2_GetRandom: 하드웨어 엔트로피 기반 고품질 암호학적 난수 생성.
    • TPM2_Quote: 원격 증명(Remote Attestation)용 하드웨어 서명 증명서 발급.
  • 호환성: tpm2-tools 및 TSS2 표준 라이브러리와 수정 없이 100% 연동.

eMMC RPMB 기반 Anti-Rollback 방어 메커니즘

스토리지 스냅샷 복제를 통한 이전 상태 복원(Rollback) 공격 차단:

  • RPMB (Replay Protected Memory Block):
    • eMMC/UFS 플래시 하드웨어 컨트롤러 내부의 보안 파티션.
    • OP-TEE가 보유한 공유 비밀키(EKB Tag 유도)로 서명된 HMAC-SHA256 패킷만 수락.
  • 단조 증가 카운터 (Monotonic Write Counter):
    • 쓰기 작업 시마다 하드웨어 내부 카운터가 1씩 자동 증가.
    • 공격자가 이전 스냅샷(Counter 101)을 재주입하더라도, 현재 카운터(102)와 불일치하여 즉시 거절 (TEE_ERROR_SECURITY).

🔴 Red Team 공격

  • 루트 권한 커널에서 TZDRAM 주소(0x0e100000)로 직접 DMA 읽기 시도.
  • fTPM의 이전 NVRAM 스냅샷 블록을 캡처하여 과거 상태로 덮어쓰기 시도.

🔵 Blue Team 방어

  • ARM TrustZone 하드웨어 메모리 방화벽이 버스 트랜잭션을 거부하여 Fault 발생.
  • RPMB 단조 증가 카운터 검증으로 과거 프레임 재전송 즉각 차단.

핵심 요약 (Key Takeaways)

  • 하드웨어 기반 신뢰 분리: 리눅스 커널이 침해되어도 TEE 내부의 암호 자산 및 fTPM은 안전 유지.
  • 표준 TCG TPM 2.0 지원: /dev/tpmrm0를 통해 표준 도구(tpm2-tools, OpenSSL)와 무수정 연동.
  • 영구 Anti-Rollback 보장: RPMB 하드웨어 단조 증가 카운터로 과거 펌웨어 및 키 복원 방지.
