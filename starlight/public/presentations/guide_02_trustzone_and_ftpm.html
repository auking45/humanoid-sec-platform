The Problem

소프트웨어 보안의 한계

"커널(Ring 0)이 뚫리면 소프트웨어 보안은 끝장난다"

안티바이러스, 방화벽, SELinux는 모두 커널 내부에서 동작하는 소프트웨어임.
해커가 커널 취약점을 공격해 루트 권한을 얻으면, 이 모든 방어 도구를 메모리에서 무력화할 수 있음.

👉 해결책: 커널조차 절대 침범할 수 없는 하드웨어 레벨의 보안 구역(TrustZone) 필요!

Hardware Partitioning

두 개의 세계 (Normal vs Secure)

Normal World (REE)

  • 우리가 쓰는 Ubuntu 24.04 리눅스
  • 사용자 애플리케이션 (ROS 2, AI 모델)
  • 언제든 해킹당할 수 있다고 가정 (Zero-Trust)
  • CPU 버스 신호: NS=1 (Non-Secure)

Secure World (TEE)

  • 초경량 보안 OS: OP-TEE Core
  • 보안 앱: fTPM 2.0 TA, PKCS#11 TA
  • 외부 네트워크에 직접 노출되지 않음
  • CPU 버스 신호: NS=0 (Secure)

메모리 컨트롤러 하드웨어가 NS 비트를 검사하여 Normal World의 Secure RAM 접근을 물리적으로 차단함.

Context Switching

SMC (Secure Monitor Call)

일반 함수 호출이 아닌 하드웨어 트랩 명령(smc #0)으로만 전환:

  1. 리눅스 커널: 파라미터를 레지스터에 싣고 smc #0 명령 실행
  2. EL3 Monitor (TF-A): 최고 특권 모드로 트랩되어 CPU 레지스터 백업
  3. 세계 전환: 하드웨어 NS 비트를 0으로 변경 후 OP-TEE(S-EL1)로 전환
  4. 암호 연산 수행: fTPM/PKCS#11이 Secure SRAM에서 안전하게 서명 생성
  5. 결과 반환: 다시 SMC를 통해 결과값만 리눅스에 전달
Cost & Physical Security

dTPM(외장 칩) vs fTPM(펌웨어)

비교 항목 외장 dTPM OP-TEE fTPM (우리 플랫폼)
물리적 보안 I2C/SPI 버스 스니핑에 취약 SoC 온칩 실행 (버스 스니핑 불능)
추가 BOM 비용 \$2 ~ \$5 / 대당 \$0 (추가 부품 비용 없음)
연산 속도 느린 직렬 버스 속도 한계 초고속 온칩 메모리 속도
표준 준수 TCG TPM 2.0 완벽 준수 TCG TPM 2.0 완벽 준수 (ms-tpm-20-ref)
Mathematical Guarantee

PCR 해시 연쇄 (Extend)

"쓰기(Overwrite)는 불가능하다. 오직 확장(Extend)만 존재한다."

PCR 10_new = SHA-256( PCR 10_old || SHA-256(실행된 바이너리) )

  • 바이너리가 실행될 때마다 리눅스 커널 IMA가 해시를 계산하여 PCR 10에 Extend
  • 불가역성: 한 번이라도 악성코드가 실행되면 PCR 10은 즉시 오염됨
  • 루트 권한을 가진 해커도 과거의 정상 PCR 값으로 되돌릴 수 없음 (수학적 보증)
Anti-Rollback

RPMB (Replay Protected Memory)

롤백 공격(Rollback Attack): 정상 암호문이라도 "과거의 취약했던 구버전 파일"로
파티션을 덮어쓰면 시스템이 구버전 보안 결함 상태로 되돌아감!

eFuse 공유 인증키

플래시 메모리 컨트롤러와 SoC eFuse만 알고 있는 비밀키로 쓰기 데이터 MAC 인증.

단조 증가 카운터

쓸 때마다 하드웨어 카운터가 +1 증가.
과거 카운터로 작성된 구버전 데이터는 즉각 거절!

Key Takeaway

핵심 요약

  • TrustZone: 리눅스가 장악되어도 Secure World 메모리는 물리적으로 침범 불가
  • fTPM 2.0: 외장 칩 없이 $0 비용으로 온칩 버스 스니핑 없는 TPM 제공
  • PCR 10 Extend: 실행된 소프트웨어의 해시를 비가역적으로 하드웨어에 누적
  • RPMB: 단조 카운터를 통해 롤백/다운그레이드 공격을 원천 차단
