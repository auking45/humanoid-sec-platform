Linux IMA 측정, fTPM PCR 10 & 원격 증명

스텔스 악성코드 탐지, 하드웨어 서명 Quote 및 제로 트러스트 관제 인가

Linux IMA • fTPM 2.0 PCR 10 • TPM2_Quote • Anti-Replay Nonce • Fleet Verifier

원격 증명(Remote Attestation)이 왜 필요한가?

⚠️ 정적 헬스체크 보고의 한계

  • 단순 JSON 상태 보고("status: OK")는 감염된 악성코드가 위조 가능.
  • 공격자가 이전에 캡처한 정상 통신 패킷을 재전송(Replay)하여 관제를 속임.
  • 런타임에 실행된 비인가 바이너리가 관제망에 적발되지 않는 스텔스 위협.

🛡️ 하드웨어 기반 원격 증명

  • 모든 실행 파일 해시가 커널 IMA를 통해 fTPM PCR 10에 연쇄 기록.
  • 관제 센터가 매번 발행하는 일회용 암호학적 챌린지(Nonce) 바인딩.
  • fTPM의 Attestation Key(AK)로 하드웨어 서명된 증거만 관제망이 인가.

원격 증명 실행 시퀀스 (Archify)

Nonce 챌린지 발급 → IMA 로그 수집 → TPM2_Quote 서명 → 증거 검증 → TRUSTED 인가

Linux IMA 측정 및 PCR 10 해시 연쇄

프로세스가 실행될 때마다 하드웨어 PCR 레지스터에 기록되는 수학적 불변 체인:

  • IMA Policy (ima_policy=tcb):
    • 루트 권한 프로세스를 포함하여 실행되는 모든 ELF 바이너리 및 라이브러리 해시 측정.
  • PCR 10 Extend 연산 (SHA-256):
    • 수식: PCR[10] = SHA256( PCR[10] || SHA256(Binary_Content) )
    • 단방향 해시 함수로 누적되므로, 과거 상태로 되돌리거나 특정 실행 기록만 은폐 불가.

원격 증명 번들 (Attestation Bundle) 구조

로봇의 apps/attestation_agent/가 조립하여 관제 서버로 전송하는 증거 페이로드:

{
  "nonce": "a4f8c92b...",
  "quote": {
    "attest_data": "<TPMS_ATTEST_STRUCT_BASE64>",
    "signature": "<ECDSA_AK_SIGNATURE_BASE64>",
    "pcr_composite": { "10": "c8e23f1a..." }
  },
  "ima_log": [
    { "pcr": 10, "hash": "e3b0c44...", "path": "/usr/bin/ros2" },
    { "pcr": 10, "hash": "7a8b9c0...", "path": "/opt/ros/controller" }
  ],
  "storage": {
    "roothash": "022ddfb8...",
    "signature_file": "verity.roothash.sig"
  }
}

관제 센터 평가 엔진 (Fleet Verifier)

apps/attestation_agent/verifier.py의 4단계 엄격 평가 알고리즘:

  1. Nonce 신선도 (Freshness Check): 서버가 직전에 발급한 일회용 난수와 일치하는가? (재전송 방지)
  2. AK 인증서 유효성: Quote를 서명한 공개키가 등록된 DeviceEnrollmentCA 체인에 속하는가?
  3. IMA 로그 재현 검증: IMA 로그 항목들을 순서대로 재해싱한 합성 값이 Quote의 PCR 10과 100% 일치하는가?
  4. dm-verity 서명 검증: 보고된 스토리지 Root Hash가 DmVeritySigningKey로 유효하게 서명되었는가?

실증 검증: ATK-04 스텔스 악성코드 및 Replay 방어

🔴 Red Team 공격

  • 비인가 쉘코드를 실행하여 PCR 10이 변경되었으나, IMA 로그에서 해당 항목을 삭제 위조.
  • 과거 정상 상태에서 캡처해 둔 Attestation Bundle을 가로채 재전송(Replay).

🔵 Blue Team 방어

  • 로그 재계산 결과와 fTPM PCR 10 간 불일치가 즉각 탐지되어 UNTRUSTED 판정.
  • 재사용된 Nonce는 즉시 만료 처리되어 Replay 공격 원천 차단.

핵심 요약 (Key Takeaways)

  • 은폐 불가능한 런타임 감사: 모든 실행 파일이 fTPM 하드웨어 레지스터에 연쇄 누적되어 기록 은폐 불가.
  • 재전송(Replay) 공격 완전 차단: 매 검증 시마다 발행되는 Nonce 기반 챌린지-응답 구조.
  • 자율 제어 인가 게이트: 증명 결과가 TRUSTED인 정상 로봇만 클라우드 관제 및 미션 수행 허용.
